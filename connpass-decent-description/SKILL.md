# connpass の説明文を、申し込まれる形に組む

長い散文は読まれない。connpass の説明欄で申込率を落とす原因はほぼ 2 つに絞られる。

- **順番が悪い** — 判断材料（誰が何を話すのか）が下にあり、読む人が到達する前に離脱する
- **走査できない** — 段落が続くだけで、太字も表もパネルもないので、目が止まる場所がない

この skill はその 2 つだけを扱う。文章の内容そのものの良し悪しには踏み込まない。

## 最初に読むもの

| 何を知りたいか | どこを読むか |
| --- | --- |
| connpass が通す記法・タグ・CSS | `connpass-syntax` skill の `references/syntax.md` |
| GDG のパレット・ロゴ・ステッカー・構成原則 | `gdg-design` skill の `references/brand-system.md` |
| 上の 2 つを connpass 上で合成する具体的な組み方 | 本 skill の [references/design-guidelines.md](references/design-guidelines.md) |

記法とブランドの定義は上記 2 skill が唯一の情報源で、ここには複製しない。
サニタイザが再計測されたときに片方だけ古くなるのを避けるためである。

書き始める前に `references/design-guidelines.md` を読む。
`assets/meetup-template.html`（単一トラック）と `assets/conference-template.html`（複数トラック）は
そのまま埋められる完成形なので、近いほうを下敷きにするとゼロから組むより速く、確実に規則を守れる。

## 1. 材料を棚卸しする

書き始める前に、揃っているものと欠けているものを確認する。

- イベント名 / キャッチコピー / 何をするイベントか
- 公式サイト URL、日時、会場（住所・フロア）、参加費
- バナー画像の URL
- セッションごとに: タイトル、概要、登壇者名、所属、肩書き、アイコン URL、自己紹介、SNS
- タイムテーブル（トラック数、休憩、受付・終了時刻、懇親会の有無）
- 主催・共催の団体名と紹介文
- 持ち物、定員、懇親会などの補足
- **そのイベントの支配色**（指定がなければ Blue を既定にする）

**欠けているものは推測で埋めない。** 開催時刻も会場も登壇者の肩書きも、埋めれば
イベント運営の事実を捏造したことになる。足りない材料はユーザーに聞く。
聞くまでもなく決まるもの（支配色、ステッカーの選択、セクション見出しの文言）は自分で決めて進める。

## 2. 掲載順を決める

この順番が申込率に効く。上から読んで「申し込むかどうか」を決められる並びになっている。

| # | セクション | 役割 |
| --- | --- | --- |
| 1 | `# {{イベント名}}` | 何のイベントか |
| 2 | 2〜3 行の説明文 | 離脱される前に価値を伝える |
| 3 | 一目サマリ（表または画像） | セッション・登壇者・テーマを一望させる |
| 4 | 開催概要 | 公式サイト・日時・会場・参加費 |
| 5 | タイムテーブル | 1 列目が時間、2 列目以降がトラック |
| 6 | セッション詳細 | 各セッション + 登壇者プロフィール |
| 7 | 主催 | |
| 8 | 共催 | |
| 9 | アンチハラスメントポリシー | |
| 10 | Code of Conduct | |

外してはいけない判断が 2 つある。

- **3 を散文にしない。** ここは「行く価値があるか」を判断する位置で、
  読む人が最も注意を払っている。文章ではなく、アイコンと名前が並んだ表か 1 枚の画像を置く
- **Opening と Closing はセッション詳細の一番下**に置く。時系列どおり先頭に置くと、
  本題のセッションが下に押し下げられる。タイムテーブルには時系列どおり並べてよい

7〜10 は装飾しない。素の Markdown で書く（`assets/boilerplate-ja.md` にある定型文を貼る）。
ここは判断材料ではなく、必要になったときに探す情報なので、視線を奪う価値がない。

## 3. 走査できる形にする

読む人はまず全体をスクロールして、目が止まった場所だけを読む。止まる場所を作るのが装飾の仕事である。

- **段落は 2〜3 行で切る。** `line-height` は connpass に消されるので、
  間隔は `<p>` を分けて `margin` で作る
- **太字・箇条書き・表・パネル**に割る。散文 5 行より、太字の見出し + 3 項目の箇条書きのほうが読まれる
- **絵文字は見出しや項目名の先頭に置く**と視線の足がかりになる。
  リテラルの Unicode（🌐 📅 📍 🎫 💻）を使う。`:calendar:` 形式のショートコードは
  `connpass-syntax` の検証範囲外なので依存しない
- **1 セクション 1 メッセージ。** パネルを跨いで話を続けない

### 画像化を選ぶ基準

情報密度が高い塊は、HTML で組むより 1 枚の画像にしたほうが読みやすいことがある。

| 画像にする | HTML で組む |
| --- | --- |
| 4 トラック以上のタイムテーブル | 3 トラック以下 |
| 登壇者 5 名以上の一覧 | 4 名以下 |
| ロゴが並ぶスポンサー一覧 | 文字だけで足りるもの |

画像にするときは `gdg-design` で作り、`gdg-img` で `img.gdgs.jp` にアップロードして URL を得る。
**画像だけで完結させない。** 登壇者名やセッションタイトルのテキストを必ず併記する。
画像内の文字は検索にも読み上げにも乗らず、スマートフォンでは拡大しないと読めない。

## 4. 見た目を組む

具体的な HTML は [references/design-guidelines.md](references/design-guidelines.md) にある。
守るべき規則は 3 つだけで、残りはそこからの帰結である。

1. **パネルは白地 + Black 02 の枠線** — `background-color:#FFFFFF; border:2px solid #1E1E1E;`。
   **セクションはすべてパネルで囲む**（見出しもパネルの中に入れて 1 セクション = 1 枚のカードにする）。
   片側だけの罫（`border-left:6px solid` のようなアクセントバー）は GDG の形ではないので使わない
2. **色は表のセルにだけ置く** — パネルを全部同じ白にすることで、
   色が出てきた場所が「意味のある場所」になる。Pastel の面を使うのは、
   色が分類を表しているセル（タイムテーブル、トラック凡例）だけ。
   イベントの支配色は、登壇者アイコンのキーラインのような**線**として効かせる
3. **装飾の階層は 1 段まで** — Off White の地 `<div>` はページに 1 枚。
   その直下に置けるのはバナー画像とパネルだけで、パネルの中にパネルを入れない。
   表のセルの色付けはパネルではないので、タイムテーブルはパネルの中に入れてよい

### タイムテーブルの規約

- 1 列目は時間（`19:00` または `10:00〜10:30`）。2 列目 = Track A、3 列目 = Track B、…
- 1 セルにセッションタイトル（`<strong>`）と登壇者名を入れる
- **時間列は素のテキスト**にして、色はセッション列だけが持つようにする
- **受付・休憩・終了・懇親会は減光する** — 枠 `#9AA0A6` / 地 `#F0F0F0` / 文字 `#9AA0A6`、
  `font-size:14px`、太字にしない。本題と同じ強さで置くと、
  タイムテーブル全体が等価な行の羅列に見えて走査できなくなる
- 全トラック共通の休憩は `colspan` で 1 セルにまとめる

### 横並びにするときの罠

横方向にコンテンツを並べるには、枠線を消したテーブルを使う（`border:none` を table・td 両方に）。

このとき、画像だけの列があると隣の列のテキストが画像のかなり下から始まってしまう。
セルの既定の縦位置が中央揃えで、`vertical-align` は connpass のサニタイザに消されるためである。
**画像セルの先頭に全角スペースだけの段落 `<p>　</p>` を置く**と画像が 1 行分下がり、
テキストの開始位置が画像の上端に近づく（実測でずれが 63px → 36px）。
完全に揃うわけではないので、そこは詰めなくてよい。

なお、表は中身の幅に縮む。CSS の `width` は消え、`table` は `width` 属性も受け付けないので、
**全幅にする手段はない。** 縮む前提で列数と 1 セルあたりの文字量を決める。

```html
<td style="border:none; padding:0 18px 0 0;">
  <p>　</p>
  <img src="{{アイコンURL}}" alt="{{登壇者名}}" width="160" style="border:3px solid #4285F4;" />
</td>
```

## 5. 納品前に検証する

```bash
python3 scripts/lint_connpass.py path/to/description.html
```

エラー（サニタイザに消される）とワーニング（GDG ブランドに反する）を行番号つきで報告する。
**両方 0 になるまで直す。** 特に `border-width` + `border-style` + `border-color` の個別指定は、
ブラウザでは正しく見えるのに connpass では 3 宣言とも消えて枠線が丸ごと消滅する。
公開してから気づく類の失敗なので、必ず機械に検査させる。

スクリプトが通ったら、目視で残りを確認する。

- 掲載順が §2 の表のとおりか。Opening / Closing がセッション詳細の最下部にあるか
- 開催概要に公式サイト・日時・会場・参加費の 4 項目が揃っているか
- 休憩行が確かに沈んで見えるか
- 登壇者ごとに 名前 / 所属・肩書き / アイコン / 自己紹介 の 4 つが揃っているか
- 推測で埋めた事実が混ざっていないか

## 6. 渡し方

connpass の説明欄にそのまま貼れる形で渡す。

- チャットに見せるときだけフェンスで囲む。**貼り付け用のファイルにフェンスを含めない**
- 地の `</div>` から下（主催・共催・アンチハラスメント・CoC）は素の Markdown のまま置く
- 埋められなかった `{{...}}` が残っているなら、何が足りないかを明示して渡す。
  黙って消すと、抜けたまま公開される
