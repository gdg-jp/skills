# connpass の説明文を、内容を壊さず読みやすくする

この skill は、イベント固有の内容と既存デザインの意図を保ちながら、connpass 上で読みやすく、
申し込みを判断しやすい説明文へ整えるためのものである。

汎用テンプレートへ当てはめることは目的ではない。イベントごとに必要な情報、見出し、掲載順、
色の意味は異なる。ユーザーと内容を確定してから、必要な範囲だけ構造と見た目を改善する。

## 情報源の優先順位

判断が衝突した場合は、次の順で優先する。

1. ユーザーが明示した要件と、対話で承認された内容
2. 既存ファイルにある、意図を持って作られた構成・文言・色分け・CSS
3. 本 `SKILL.md` の判断基準
4. 参照ガイドとテンプレートの例

作業に必要な資料:

| 目的 | 読むもの |
| --- | --- |
| connpass が通す記法・タグ・CSS | `connpass-syntax` skill の `references/syntax.md` |
| GDG のパレット・ロゴ・ステッカー | `gdg-design` skill の `references/brand-system.md` |
| connpass 向けの実装例 | [references/design-guidelines.md](references/design-guidelines.md) |

`references/design-guidelines.md` と `assets/*.html` は実装パターンの例であり、コンテンツ構成の仕様ではない。
そこにある固定掲載順、一目サマリ、全セクションのパネル化、ステッカーの統一、固定の減光色、
単一トラックの単色化、Opening / Closing の詳細化を必須事項として扱わない。

## 1. コンテンツは対話で確定する

文章やHTMLを書き始める前に、材料と既存構成を棚卸ししてユーザーに提示する。

- イベント名、目的、対象者
- 日時、会場、参加費、公式URL
- 既存セクションとその掲載順
- セッション数、登壇者情報、タイムテーブル
- 持ち物、飲食、懇親会、注意事項
- バナー、登壇者画像、装飾画像
- 既存の色分けと、それぞれが表す意味

次の変更は、実装前に候補を示し、ユーザーの明示的な合意を得る。

- セクションの追加、削除、改名、統合、分割、並べ替え
- 本文や箇条書きの削除または要約
- 「一目サマリ」「参加前にご確認ください」など、元にないセクションの追加
- 「講師」を「セッション詳細」に変えるなど、イベントの見せ方を変える編集
- Opening / Closing を本文の独立項目として扱うこと
- タイムテーブルの色の意味を変えること

「enhance」「読みやすくして」という依頼だけでは、全面的な再構成への同意とはみなさない。
まず、残すもの・変えるもの・追加しないものを短い対話で確定する。

不足している開催事実は推測しない。必要な情報を質問し、回答を待つ。
未確定値をプレースホルダーで残す場合も、先にユーザーへ確認する。

## 2. 既存ファイルは最小差分で改善する

既存の説明文がある場合は、意図のある表現を初期値として尊重する。

- 見出し、掲載順、訴求文、箇条書きを勝手に削除しない
- 既存の「こんな方におすすめ」のような走査しやすい情報を、散文へ圧縮しない
- 色分けが内容の種類を表している場合、その対応を確認せず変更しない
- サニタイザ非対応CSSを直すときも、元の見た目の目的を特定して代替する
- lintやテンプレートへの適合を理由に、良く機能している表現を置き換えない

変更案が複数ある場合は、元の意図を最も保つ案を先に提示する。

## 3. 構成はイベントに合わせる

必須のセクション順は設けない。読者が早い段階でイベントの価値、日時、場所、参加条件を判断できる
ことを目標にし、具体的な構成は対話で決める。

- 一目サマリは、登壇者やトラックが多く一覧性が実際に上がる場合だけ提案する
- 単一セッション・単一講師なら「講師」セクションで十分なことが多い
- 複数セッションなら、セッション詳細やトラック別構成を提案できる
- Opening / Closing は、説明すべき固有内容や登壇者情報がある場合だけ本文へ載せる
- 持ち物や軽食は、情報量と重要度に応じて開催概要、注意事項、既存セクションのいずれかへ置く
- 独立した案内パネルは、それ自体が読者の判断や行動を明確に助ける場合だけ提案する
- 主催、共催、アンチハラスメントポリシー、Code of Conduct の形式も既存ページとユーザーの希望を優先する

セクションを増やすこと自体を改善とみなさない。重複する説明は作らない。

## 4. 走査しやすさを整える

内容が確定した後で、必要な箇所だけ視線の足がかりを作る。

- 長い段落は意味の切れ目で分ける
- 太字、箇条書き、表、画像は、情報の比較や発見が速くなる場合に使う
- パネルは情報のまとまりを明確にする場合に使い、すべてのセクションへ強制しない
- 1つのパネルへ無関係な情報を詰め込まない
- 画像だけで情報を完結させず、重要な名前やタイトルはテキストでも残す

### 見出し用ステッカー

見出しごとに、意味や構図に合う様々なGDGステッカーを選ぶ。
すべての見出しを同じステッカーへ統一しない。反復に意図がある場合だけ同じものを再利用する。

- 公式サイトやオンライン情報には globe
- 次の行動を示す箇所には arrow
- 共同開催には plus や multiply
- タイトルを囲む場合は左右の brace や bracket のペア
- 技術セクションには hash、asterisk、angle brackets など

ステッカーは装飾なので原則 `alt=""` とし、`height` 属性だけで大きさを指定する。

## 5. 見出しとパネル

connpass の既定装飾が黒い枠線の上へ見えないよう、カード先頭の `h1` には厳密に
`margin:0` を指定する。

```html
<h1 style="margin:0; border:none;">{{イベント名}}</h1>
```

`margin:0 0 12px 0` のように下マージンを足した値へ置き換えない。
見出し後の間隔は、次の要素の `margin-top` またはカードの `padding` で作る。

パネルを使う場合は、GDGの基本形として白地、Black 02 の四辺の枠線を優先する。
ただし、既存ファイルの別の表現を変更する前に、その目的とユーザーの希望を確認する。
パネルの入れ子は本文幅で境界が読みにくくなるため避ける。

## 6. タイムテーブルの色は内容の意味で決める

配色は「トラック数」だけでなく、各行が担う意味に基づいて決める。
既存の色分けが機能している場合は保持する。

### 複数トラック

同じトラックには一貫した色を割り当て、ヘッダやラベルも併記する。
色だけでトラックを識別させない。

### 単一トラック

支配色1色へ統一する必要はない。メインセッション、Opening / Closing、交流、休憩など、
内容上の分類がある場合は異なる色を使ってよい。

### 目立たせない行

受付、休憩、終了などはメインコンテンツより目立たなくしてよいが、固定の灰色や低コントラスト文字を
強制しない。「彩度のある面色を使わない」「太字を控える」「枠線を弱める」などから、
ページ全体で十分読める方法を選ぶ。

懇親会や交流時間は、イベントの主要コンテンツなら減光しない。
Opening / Closing もメインセッションと意味が異なる場合は、同色へ統一せず区別する。

時間列、タイトル、登壇者名の配置は、既存表の読みやすさを保ちながら調整する。

## 7. connpassで壊れないHTMLにする

記法とCSSの許可範囲は `connpass-syntax` の `references/syntax.md` を正本とする。

- `border-radius`、`line-height`、`display`、CSSの `width` など、消される指定へ依存しない
- 枠線は `border:2px solid #1E1E1E` のような許可されたショートハンドで書く
- 画像寸法は `width` または `height` 属性を使い、縦横比を壊さない
- 横並びには枠線なしの表を使えるが、表が内容幅へ縮む前提で設計する
- `vertical-align` へ依存しない

## 8. 検証する

```bash
python3 scripts/lint_connpass.py path/to/description.html
```

サニタイザ非対応によるエラーは0件になるまで直す。
ブランド警告は、ユーザーが承認した意図と矛盾しないものだけ直す。
承認済みの表現を壊して警告0件にすることを目的にしない。

最後に次を自己監査する。

- 実装した追加・削除・改名・並べ替えが、対話で承認された範囲内か
- 既存の見出し、訴求、色の意味、CSS上の工夫を不用意に失っていないか
- `h1` が厳密な `margin:0` を保っているか
- 単一トラックへ単色制約を適用していないか
- 受付や終了は読めるまま主役より控えめか
- 懇親会など主要コンテンツを誤って減光していないか
- 推測で補った開催事実がないか

## 9. 渡し方

connpass の説明欄へそのまま貼れる形で渡す。

- 貼り付け用ファイルにMarkdownフェンスを含めない
- 未確定値や意図的に残したlint警告があれば明示する
- 変更したコンテンツ構成と、ユーザー確認どおり保持した要素を短く報告する
